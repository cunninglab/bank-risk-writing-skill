# Skill 质量原则与标准

本文件是本项目 skill（`skills/*/SKILL.md` 及其 `references/`、共享内核）的评审基准。
新增、修改或删除 skill 内容时，以本文件为唯一判据；与本文件冲突的旧做法（含 2026-06 Darwin 一轮增补的失败模式表与 🔴 STOP 卡点）按本文件重新评估。

- 版本：2026-11-09，首版
- 外部参考：`alchaincyf/huashu-report`（commit `eda161c`，MIT），只借鉴思路，不搬原文
- 写作指南依据：`writing-for-agents`（单一事实来源、无操作检验、完成判据、正面表述）；Anthropic `skill-creator`（SKILL.md 精简、按需加载、引用一层深）

## 一、第一性原理推导

### 1. skill 是什么

skill 是任务发生时载入模型上下文的指令。它的价值只有一个来源：**载入后模型行为与默认行为的差**，并且这个差落在用户在意的方向上。
它的成本是三项：每次载入占用的上下文与注意力、与其他指令冲突的风险、维护负担。
由此直接得出：一条不改变默认行为的指令只有成本；一条改变了行为但方向无据的指令有风险。

### 2. 这个领域的用户与代价

用户是银行风险管理、政策研究岗位的人员，产出会进入正式文稿，被审稿人或管理层阅读。代价不对称：

| 失效类型 | 例子 | 代价 |
|---|---|---|
| 事实失效 | 编造条款、把转述当原文、把“可能”写成“将” | 最高：错误进入正式文件，事后难追回 |
| 用途失效 | 给领导的汇报写成条款复述；报告提纲是通用模板 | 高：产出不能直接用，返工 |
| 增量失效 | 只有“文件说了什么”，没有“合起来意味着什么” | 中：能用，但只是资料汇编 |
| 表达失效 | 套话、媒体腔、冗长 | 低：读者可自行修改 |

四类按此顺序**字典序**比较：前一类不过关，后一类再好也不算合格。

### 3. 模型的默认行为

在本领域，模型默认能写出通顺的正式中文；默认会做错的是：顺着上下文补出看似合理的事实、把限定语弱化、给出套模板的结构与目录式标题、把汇总当作分析、用套话填充篇幅。
skill 的指令应当瞄准这些默认偏差；“正式、审慎、中性”这类形容词列表大概率是无操作，需由消融证明其作用，否则删除。

### 4. 推导出的现状问题

- 同一含义在一个 skill 内重复 3–4 处（Writing Rules / Output Contract / Hard Rules / Final Self-Check），共享规则又在 `rules/` 六个文件与项目 `CLAUDE.md` 中重复。
- formal-polish 的卡点要求“不得在同一次输出中跳过用户确认直接给出修订稿”，与项目 `CLAUDE.md` 的 Collaboration Norm（能安全给出部分结果时不追问）冲突。
- 大量规则以禁令形式出现，且没有理由与正反例，难以泛化。
- 规则的出处不可追溯；上一轮增补以评分维度为依据，没有行为证据。
- `prompts/task-routing.md` 的“不引入新事实”与已决定开放的检索能力冲突，需改为“不引入无出处事实”。

## 二、原则

**P1 边际行为。** 每条指令必须改变模型的默认行为。判据：删掉这条指令，产出会不会变差？不会就删。争议不靠讨论解决，靠消融实验（P9）。

**P2 失效模式驱动。** 每个机制必须指明它防的是哪一类失效（第一节表），并按失效代价排优先级。事实类机制优先于表达类机制。

**P3 读者用途先行。** 开工先确定两件事：读者拿它做什么（决定形态与详略），以及全文的一句话结论或任务结果是什么。写不出一句话结论，说明材料还不足以成文，应如实说明。外部基准归入 P5。

**P4 证据链。** 先建依据清单再写正文：每条事实带来源、来源级别、是否已打开原文核对。事实、基于材料的判断、建议三层分开写。来源分级与检索规则见共享内核。

**P5 受约束的研究增量。** 在事实层之上，做四件事：
- 解释“为什么”：以两个以上竞争解释给出，标为判断，并写明现有证据能否区分；
- 定位：相对既有框架（上一版文件、既有规则体系、已有公开研究的判断），本次材料印证了什么、修正了什么、补上了什么；
- 外部基准：与同业或行业公开数据对照；
- 局限与替代解释：哪些解释已排除、哪些未排除。

定位与外部基准依赖检索：检索得到的写出处，检索不到的写明缺了什么、削弱哪条结论。增量永远不升级事实的确定性。

**P6 可检查。** 每条规则同时附理由和 ❌/✅ 对照，能给判定测试的给判定测试（例如：“删掉这句，读者对结论的判断会不会变？不变就删”）。自检项必须能在产出里直接观察到。正面写出目标行为；禁令只保留为硬护栏，并配正面目标。

**P7 单一事实来源与按需加载。** 每个含义只在一处出现：跨 skill 的不变量只写在共享内核；每次运行都需要的步骤写在 `SKILL.md`；只有部分分支需要的内容放入该 skill 的 `references/`，由 `SKILL.md` 中写明“何时读”的指针引用，引用只有一层深。

**P8 运行时中立、少打断。** 正文不绑定某个运行时的工具名，写“检索公开资料并打开原文核对”。只有当继续执行会产出误导性交付、且检索无法补救时才停下询问；其余情况交付带边界标注的结果。

**P9 证据决定去留。** 机制的保留需要消融证据；领域写作规则（如“页标题写结论”）需要出处：公开样本、项目 `CLAUDE.md`，或消融结果。两者都没有的内容删除。不变量（第五节）不做消融。

## 三、标准

### A. 文件层（静态可查）

| 编号 | 标准 | 检查方式 |
|---|---|---|
| A1 | `SKILL.md` 正文（不含 frontmatter）不超过 160 行 | 行数 |
| A2 | `SKILL.md` 只含：定位、开工前必答、工作顺序（每步有完成判据）、本 skill 特有规则、交付前自检、`# Additional Resources` | 读 |
| A3 | 同一含义在 SKILL.md、references、共享内核之间只出现一次 | 逐条比对 |
| A4 | 每条规则附理由与 ❌/✅ 对照；理由写在规则旁，对照可放在该 skill 的 references（不变量的对照放在共享内核） | 逐条 |
| A5 | 每个自检项可在产出中直接观察 | 逐条 |
| A6 | 禁令仅作硬护栏且配正面目标 | 逐条 |
| A7 | 正文无运行时专属工具名（frontmatter `allowed-tools` 除外） | 搜索 |
| A8 | references 只有一层引用深度；超过 100 行的文件开头有目录；每个指针写明何时读 | 读 |
| A9 | `# Additional Resources` 只列运行时依赖，不列 `test-cases/` | 读 |
| A10 | 正文中文；frontmatter 键名、工具名、路径保留英文 | 读 |
| A11 | `npm test` 通过 | 命令 |

### B. 机制层

| 编号 | 标准 |
|---|---|
| B1 | 每个机制在机制登记表中登记：名称、防的失效类型、目标判据（C 层中的哪几条）、所在位置、消融结论及证据路径 |
| B2 | 没有消融证据支持的机制不保留；不变量除外 |
| B3 | 领域写作规则附出处（公开样本路径、`CLAUDE.md` 段落或消融记录） |

“机制”指 SKILL.md 中不变量与输出契约之外、可以整体删除而 skill 仍能运行的步骤或规则块，本轮候选为“先建依据清单”（防事实失效）与“研究增量”（防增量失效）。有项目 `CLAUDE.md` 出处的领域规则（如 PPT 页标题观点化）按 B3 处理，不计为机制。

### C. 输出层（评审判据）

C1 为闸门，任一条不通过即判该输出不合格。C2–C4 逐条评分，锚点统一为：

- **0**：缺失，或违反该条；
- **1**：有，但不完整（例如只给一个解释、未标为判断、只覆盖部分章节）；
- **2**：完整满足该条文字。

**C1 事实闸门**
- C1.1 无输入与检索结果中均不存在的事实、数字、日期、机构、文件名、条款
- C1.2 正文中每条检索得来的事实写明发布机构、标题、日期、URL，并附一句支撑该事实的原文摘录。核验分两步，缺一不可：
  - **打开记录（日志机械核对）**：Codex `--json` 中 `type: "web_search"` 条目的结果里，该 URL 对应的 `ref_id` 形如 `turnNviewM`；仅有 `turnNsearchM`（搜索命中）不算打开。日志正反例见 `docs/experiments/2026-11-09-skills-upgrade/evidence/`（codex-cli 0.166.0）。
  - **正文核对（独立取证）**：日志不记录页面正文是否加载，因此由实验操作者独立打开该 URL，确认摘录出现在页面中，并把取证结果存档。

  未打开、正文未加载、或摘录无法在页面中找到的内容，只能进入“待核实线索 / 需补充来源”清单，不得作为正文事实或结论依据。日志缺失、无法解析，或独立取证打不开页面时，本条记为不可判定，该输出按不合格处理。
- C1.3 三级来源（媒体、自媒体、转述）未被当作依据
- C1.4 来源区分“用户提供”与“自行检索”
- C1.5 输入中的限定语（可能、据称、初步）没有被升级为确定表述
- C1.6 无法唯一确定是哪份文件时，没有猜，而是列出候选

**C2 用途适配**
- C2.1 开头给出一句话结论或任务结果
- C2.2 形态与详略符合读者用途（如管理层汇报版结论先行、篇幅精简、待核实事项不省略）
- C2.3 结构来自材料，不是通用模板

**C3 研究增量**（policy-brief、report-outline、ppt-outline）
- C3.1 至少一处“为什么”的分析，以两个以上竞争解释给出，标为判断，并写明现有证据能否区分
- C3.2 有局限与替代解释
- C3.3 外部基准已检索并注明出处，或明确写出缺失及其对哪条结论的影响
- C3.4 有相对既有框架的定位（印证 / 修正 / 补充），依据注明出处，或明确写出缺失

**C3′ 保真**（formal-polish 替代 C3）
- C3′.1 原文全部实质信息保留
- C3′.2 没有新增任何事实、出处或判断

**C4 表达**
- C4.1 无共享内核所列禁用表达（现位于 `rules/banned-and-caution-phrases.md`）
- C4.2 无工作过程叙述、使用说明、重复免责
- C4.3 删句测试：评审从正文挑出最可能是冗余的 5 句，逐句判断删去后是否损害读者的结论、理解、行动或核验。0 句可删记 2，1–2 句可删记 1，3 句及以上记 0
- C4.4 PPT 页标题、报告章节标题为观点句（研报查数型除外）

### D. 实验层

| 编号 | 标准 |
|---|---|
| D1 | 每个 skill 选 1 个用例，优先选一次能考验多个机制的用例 |
| D2 | 旧版与新版各跑 1 次；新版运行同时作为消融的完整组；每个机制只补 1 次“去掉该机制”的运行 |
| D3 | 胜负判定只看该机制的目标判据，C1 优先：完整组通过 C1、去除组不通过，保留；完整组不通过、去除组通过，删除。C1 相同时比较 C2–C4 目标判据合计分：完整组高 2 分及以上，保留；差值在 1 分以内为打平，补跑一对，仍打平则删除；去除组高 2 分及以上，删除 |
| D4 | **用例有效性**：机制的用例必须能触发它所防的失效（防事实失效的机制用对抗用例）。三组都在目标判据上拿满分时判为“未触发”，按打平处理 |
| D5 | **预算闭合（按最坏分支）**：`8（旧版、新版各 4）+ M（去除组）+ 2M（每个单元都补跑一对）+ 4（每个 skill 最终复验）≤ 20`，因此 M ≤ 2。M 按实验单元计数，一个单元是“一个机制 × 一个代表 skill 的用例”。两个候选机制各在一个代表 skill 上测一次；结论外推到含同一机制的其他 skill，外推是否成立由 D6 的最终复验检查。代表关系在方案中锁定 |
| D6 | **组合删除复验**：只要某个 skill 删除了机制，就对它的最终版本复跑 1 次，按 D9 与旧版比较。复验不通过时，恢复该 skill 中被删除的机制，不再追加试跑，并在报告中写明 |
| D7 | 执行：`codex [--search] exec -m gpt-6.1-terra -s read-only --json -C <变体快照>`，推理强度 `medium`；`--search` 是顶层参数，只在检索类用例上加 |
| D8 | 评审：一个看不到版本标签的 Claude subagent，在一次会话中按 C 层逐条判定，输出匿名、顺序随机；C1.2 的打开记录按日志机械核对，正文核对由实验操作者独立取证，两者都不交给评审 |
| D9 | 最终版本对旧版：C1 无退步；C2–C4 合计不低于旧版，且各机制的目标判据不低于旧版 |
| D10 | 原始输出、日志、评分存档于 `docs/experiments/2026-11-09-skills-upgrade/` |

## 四、huashu-report 优势的采纳映射

| huashu-report 优势 | 本项目的采纳形式 | 落点 |
|---|---|---|
| 规范来自实物实证 | 领域规则需有出处；定性阅读 `examples/` 的 5 份公开样本取证，写明样本局限 | P9、B3 |
| 开工前三问 | 拆开落地：读者用途沿用现有输入字段 `output_use`；一句话结论有项目 `CLAUDE.md` Default Output Structure 出处，按 B3 作领域规则；外部基准并入研究增量 | P3、B3 |
| 研究深度三层、预先反驳自己 | 竞争解释、相对既有框架的定位、外部基准、局限与替代解释；标为判断，不升级事实 | P5（机制，待消融） |
| 先建数据表再写正文 | 先建依据清单（来源、级别、是否打开核对） | P4（机制，待消融） |
| 行文判据（删句测试、发现 vs 认为、采集方 vs 分析方、标题写结论） | 删句测试、事实 / 判断分层、来源标注、观点化标题 | P6、C4 |
| 四个角色的身份设定 | 不采纳：身份设定不指向本领域任何一类失效（P2），且预算只容两个候选机制 | — |
| SKILL.md 精简与按需加载 | 共享内核加每个 skill 的 references | P7、A 层 |
| 视觉系统与渲染流水线 | 不采纳：本项目产出为文字与提纲 | — |
| 作者介绍、版本检查 | 不采纳：与任务无关 | — |

huashu-report 的规范来自英文、AI 主题的机构报告；本项目对其中任一条的采纳都需本领域出处或消融证据，不直接继承。

## 五、不变量（不做消融）

1. 项目 `CLAUDE.md` 的 Hard Prohibitions：不编造监管依据、数字、日期、机构、文件名；不暗示接触内部材料；不模仿内部模板语言；不把推断写成结论。
2. 来源分级与引用规则：一级官方原文、二级权威研究可作依据；三级只作线索；引用必须基于实际打开的 URL，并附支撑事实的原文摘录；区分用户提供与自行检索；无法联网时退回“需补充来源”清单。
3. formal-polish 不检索、不新增事实。
4. frontmatter 字段（`name`、`description`、`when_to_use`、`allowed-tools`）与 `# Additional Resources` 节的存在；`npm test` 契约。

## 六、局限

- 消融默认每组只跑 1 次，只能识别明显差异；效果小的机制会被判为打平并删除。删除结论只说明“在该用例上没有可见作用”，不说明机制在所有输入上都无用。删除记录保留在机制登记表中，可据此恢复。
- 单项消融不能证明“组合删除”安全，D6 的最终复验只覆盖每个 skill 的一个用例。
- 试跑模型是 `gpt-6.1-terra`；在 Claude 上的效果未经交叉验证。
- 评审由单个模型完成，可能有系统性偏好。
- C1.2 的正文核对依赖独立取证时页面与试跑时一致；页面在两次访问之间被修改，会造成误判。
- 机制只在一个代表 skill 上消融，外推到其他 skill 只经过一次最终复验检查。
- 本领域公开样本只有 5 份，B3 的出处覆盖面有限；样本不足以支撑的规则在登记表中标明。
