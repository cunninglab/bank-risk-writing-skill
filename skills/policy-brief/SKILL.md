# 政策简报

把公开政策、监管文件、通知或答记者问整理成结构化简报，供银行风险管理、政策研究或汇报使用。读者拿它回答三个问题：这份文件要求了什么，和以往相比有什么不同，对自己的工作意味着什么。

本 skill 不负责润色已有草稿（用 formal-polish）、搭报告提纲（用 report-outline），也不出逐页 PPT（用 ppt-outline）。

开工前先读完 `rules/core.md`。它规定了材料边界、来源分级、检索与引用、不确定性、分层写作、表达和何时停下，本 skill 全部适用，下文不再重复。

## 开工前

1. **读者用途。** 按用户说明的用途（`output_use`）决定写法：
   - **标准简报**（默认）：按下面的输出结构写全。
   - **汇报版 / 领导摘要版**：依次写核心结论、3–5 个关键点、建议关注事项；篇幅压缩，但待核实事项一条不省。
   - **要做成 PPT**：先完成本简报，再交给 ppt-outline。
2. **一句话结论。** 写下这份文件对读者最重要的一句话。写不出来，说明材料还不够，先补材料（第 3 条）。
3. **材料判断。**
   - 手上有原文：直接开始。
   - 只有文件名、链接或别人的转述：按 `rules/core.md` 第 3 节检索原文。
   - 要写“变化 / 新增 / 收紧”：还要检索上一版文件或被替代的规则，作为比较依据。

   完成判据：原文已打开核对；或者已列出候选文件 / 需补充来源，并确定只交付有边界的结果。

## 工作顺序

1. **文件概况**：主题、文件性质、发文机构、文号、发布与生效日期。只写原文载明的。
2. **核心要点**：明示要求、重点条款、约束边界、实施安排。强制性要求和鼓励性表述分开写。
3. **关键变化**：有比较依据时写“变化”，并注明比较对象；没有比较依据时，改写为“值得关注的重点”。
4. **可能影响**：分风险管理、合规、业务管理、后续研究几方面，只写材料能支撑的影响。
5. **后续关注**：列出待核实事项、待发布的细则、需要持续观察的点。

完成判据：五部分齐全，每条要点都能追溯到原文。

## 输出结构

- 一句话结论
- 文件概况
- 核心要点
- 关键变化或重点关注（没有比较依据时写“值得关注的重点”）
- 可能影响
<!-- mechanism:M2 -->
- 分析与定位（标为基于材料的判断）
<!-- /mechanism:M2 -->
- 后续关注点 / 待核实事项（含“待核实线索 / 需补充来源”；需要用户确认文件时，在这里列出候选文件）

汇报版改用“开工前”第 1 条的结构，不加其余各节，但待核实事项照样列出。

## 规则

各条规则的 ❌/✅ 对照见 `skills/policy-brief/references/examples.md`。

1. **“变化”必须写明比较对象。** 理由：没有上一版文件就说“新增”，等于编造了一次对比。
2. **背景规则和本次新增分开写。** 理由：把早已生效的规则当成本次新要求，会误导读者对工作量和时点的判断。
3. **不替读者设计内部执行方案。** 只写文件要求和可能影响；用户要执行建议时，写成“需要复核什么、澄清什么、补充什么证据”。理由：执行方案取决于机构内部情况，公开材料支撑不了。

## 交付前自检

- 开头是一句话结论。
- 每一处“变化 / 新增 / 收紧”都写了比较对象，且比较对象出现在来源中。
- 强制性要求与鼓励性表述没有混写。
- 正文中的检索事实都附了来源和原文摘录；没打开原文的内容只出现在“待核实线索”里。
- 无法确定是哪份文件时，列出了候选文件，并且没有按猜测的文件写正文。
- 汇报版：结论先行，待核实事项没有省略。
