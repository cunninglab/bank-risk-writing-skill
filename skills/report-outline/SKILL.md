# 报告提纲

基于用户提供的材料和检索得到的公开资料，生成一份可以直接据以写作的报告提纲。提纲的每一节都对应一项写作任务：这一节要回答什么问题、写哪些要点、需要什么证据。

本 skill 不负责润色（用 formal-polish）、政策要点提炼（用 policy-brief），也不出逐页 PPT（用 ppt-outline）。

开工前先读完 `rules/core.md`。它规定了材料边界、来源分级、检索与引用、不确定性、分层写作、表达和何时停下，本 skill 全部适用，下文不再重复。

## 开工前

1. **读者用途。** 按用户说明的用途（`output_use`）确定报告类型和详略：研究报告、汇报材料、同业观察或风险分析。汇报材料要结论先行、篇幅精简。
2. **一句话主线。** 写下全文要论证的一句话。写不出来，说明材料还不足以支撑完整提纲，只能交付初步框架（规则 3）。
3. **材料判断。** 确认材料能支撑什么结论、支撑到什么强度。缺原文、缺数据时，按 `rules/core.md` 第 3 节检索。

## 工作顺序

1. **定核心问题**：材料要回答的核心问题是什么，能支撑到什么结论强度。
2. **选结构**：从下面几种展开逻辑中，选与读者用途最匹配的一种，并说明理由；材料另有更合适的逻辑时，按材料的来。
   - 政策研究：背景 → 核心内容 → 关键变化 → 影响分析 → 关注点 → 后续观察
   - 风险分析：问题概述 → 主要风险点 → 成因分析 → 影响判断 → 建议措施 → 持续跟踪
   - 同业观察：披露特征 → 核心发现 → 风险变化 → 管理动作 → 可参考点与局限
   - 汇报材料：总体结论 → 关键支撑 → 主要问题 → 建议动作
3. **写各节任务**：每个一级章节写明作用；每个二级条目写明要回答的问题、要写的要点、最关键的事实或数据、需要审慎表述的地方。
4. **整合多份材料**：按主题整合，不按“材料一、材料二”逐份罗列。材料之间相互矛盾时，保留矛盾并注明各自出处。
5. **列建议补充材料**：要把报告写扎实，还缺哪些公开证据、数据、对照材料或政策原文。

完成判据：每个章节和二级条目都能从材料中找到依据，或者已标明需要补充什么证据。

## 输出结构

- 推荐标题
- 核心结论或写作主线（一句话）
- 一级提纲（各节作用）
- 二级展开建议（每条写明：回答什么问题、写哪些要点、需要哪些证据、哪里要审慎）
- 建议补充材料

材料不足时，在开头写明“以下为基于现有材料形成的初步框架”。

## 规则

各条规则的 ❌/✅ 对照见 `skills/report-outline/references/examples.md`。

1. **章节数由材料决定。** 材料只撑得起三节，就写三节，不为显得完整而增加章节。理由：空章节会让读者以为那部分已有依据。
2. **章节标题写观点或任务，不写空标签。** 查数型章节（如数据附表）可以用中性描述。理由：“风险概况”这样的标题，写作者拿到后仍不知道要写什么。
3. **材料不足时交付初步框架。** 写明能支撑的范围和缺什么材料，不把待补证据的部分写成确定内容。理由：看似完整的提纲，会被当作已经论证过的框架来用。
4. **结构选与读者用途最匹配的一种，并说明理由；** 不默认选最长、最“系统”的那种。理由：结构越长，越容易出现没有材料支撑的章节。

## 交付前自检

- 有一句话的核心结论或写作主线。
- 每个一级章节都写明了作用，每个二级条目都写明了要回答的问题和所需证据。
- 没有与材料无关的通用章节。
- 多份材料按主题整合，没有逐份罗列。
- 材料不足时，开头写明了“初步框架”，并列出了缺口。
